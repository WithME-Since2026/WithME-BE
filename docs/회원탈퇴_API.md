# 회원탈퇴 API

## 요청

- `DELETE /api/v1/users/me`
- `Authorization: Bearer <accessToken>`
- `Content-Type: application/json`

```json
{
  "reason": "서비스를 자주 사용하지 않아요",
  "opinion": "추가 의견"
}
```

`reason`은 필수이며 공백만 입력할 수 없고 최대 100자다. `opinion`은 선택이며 최대 1,000자다.
성공 시 HTTP 204를 반환한다. 프론트는 성공 후 저장된 토큰과 사용자별 캐시를 삭제하고 로그인 화면으로 이동한다.

## 처리 범위

- `users.deleted_at`을 설정하는 계정 비활성화 방식이다. 개인정보·개인 일정·todo의 물리 삭제는 포함하지 않는다.
- 본인 `group_members` 상태를 직책과 무관하게 `LEFT`로 변경한다. 기존 모임과 다른 멤버는 보존한다.
- 본인의 과거·현재 `group_responses`를 물리 삭제한다. 결석 사유도 함께 삭제된다.
- `user_withdrawals`에 사용자 ID, 사유, 의견, 생성·수정 시각을 저장한다. 사유·의견은 로그에 남기지 않는다.
- 모든 기기의 FCM 토큰과 LOCAL/KAKAO 리프레시 토큰을 삭제하고 알림 설정을 끈다.
- 로그인, 토큰 재발급 및 기존 액세스 토큰 인증에서도 탈퇴 계정을 거부한다.
- 이메일·로그인 식별자는 유지되며 동일 정보 재가입은 허용하지 않는다. 카카오 연결 해제는 포함하지 않는다.

## 모임장 처리

다른 활성 멤버가 있는 모임의 ACTIVE OWNER 탈퇴를 HTTP 409 `GROUP_409`로 거부한다.
CO_OWNER와 일반 멤버, 혼자 있는 모임의 OWNER는 탈퇴할 수 있다.
모임장은 다른 멤버에게 위임한 뒤 회원탈퇴해야 한다. 현재 별도 모임장 위임 API는 없으며 위임 API 구현은 #43 범위에 포함하지 않는다.

## 트랜잭션과 배포

계정 비활성화·멤버십 변경·참석 기록 삭제·의견 저장·FCM 삭제는 하나의 DB 트랜잭션이다.
Redis 삭제가 실패해도 DB를 롤백한다. Redis에서 먼저 삭제된 일부 토큰은 복구되지 않으므로 사용자는 재로그인이 필요할 수 있다.
실제 운영 데이터 변경은 API 요청과 배포 이후에만 발생한다.

Flyway `V16__create_user_withdrawals.sql`을 추가한다. 기존 저장소에 중복 V9/V10 파일이 있으므로
운영 환경에서 사용하는 기존 migration 정리 정책을 확인해야 한다. 기존 migration 파일은 수정하지 않았다.

## Swagger 수동 확인

운영 계정이 아닌 로컬 테스트 계정으로 실행한다.

1. 서로 다른 사용자 A/B와 모임을 만들고 A의 참석·결석 기록 및 기기별 FCM 토큰을 준비한다.
2. A의 토큰으로 공백 사유, 사유 101자, 의견 1,001자를 보내면 400이고 데이터는 유지되는지 확인한다.
3. A가 일반 멤버 또는 혼자 있는 모임장인 상태에서 정상 요청을 보내 204를 확인한다.
4. DB에서 A의 deleted_at, 모든 멤버십 LEFT, 참석 응답 0건, FCM 토큰 0건, 탈퇴 의견 1건을 확인한다.
5. B의 계정·모임·참석 응답은 유지되는지 확인한다.
6. A의 기존 액세스 토큰은 401, 기존 리프레시 토큰 재발급은 실패하고 로컬/카카오 재로그인도 거부되는지 확인한다.
7. 다른 활성 멤버가 있는 모임장으로 요청하면 409이며 계정·참석 기록·의견이 변경되지 않는지 확인한다.
8. 동일 이메일 재가입은 중복 오류로 거절되고 서버 오류가 발생하지 않는지 확인한다.

## 로컬 검증 결과 (2026-11-01)

- 컴파일과 기존 테스트를 통과했다.
- build 아래의 임시 검증 7개를 포함한 전체 102개 중 101개 통과, 1개 스킵이다.
- 실제 서비스·컨트롤러·H2 DB를 사용하고 Redis 저장소만 대체했다.
- 정상 탈퇴와 타 사용자 데이터 보존, 모임장 거부 시 무변경, 단독 모임장 탈퇴, 비활성 멤버십 정리,
  입력 검증·미인증 거부, Redis 장애 시 DB 롤백, 탈퇴 계정 토큰 재발급 차단을 확인했다.
- 정상 탈퇴 시나리오에서 기존 액세스 토큰 거부, 재로그인 거부와 중복 탈퇴도 확인했다.
- 임시 H2 환경에만 globally_quoted_identifiers_skip_column_definitions 설정을 적용해 기존 text 타입 인용 문제를 피했다.
- 팀 컨벤션에 따라 임시 검증 코드는 커밋하지 않았다. 이 문서의 Swagger 수동 확인 절차로 재검증할 수 있다.
- 운영 PostgreSQL/Flyway 마이그레이션, 실제 Redis·카카오·FCM 외부 연동은 검증하지 않았다.
